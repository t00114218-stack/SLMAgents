      📂 Local Document Extraction

      SLM Document Parser

      Extract tabular metrics, metadata structures, and key paragraphs from PDFs, Word docs, and plain text files locally under strict MIT-licensing parameters.

      Overview

      The SLM Document Parser leverages Microsoft's MIT-licensed Phi-3.5-mini-instruct model optimized via ONNX Runtime GenAI to parse multi-formatted documents offline. It parses text layouts, lists, and tables (spanning both paragraphs and Word table grid entities) to output structured JSON matching a targeted validation schema.

      🤖 Truly Agentic Workflow

      The Document Parser does not just extract text; it operates a self-correcting validation loop:

      • Layout Assembly: Paragraphs and table structures are aligned to match spatial configurations.
      • Prompt Tag Mapping: Injects text into correct Phi-3.5 instruction wrappers.
      • Schema Verification: Analyzes outputs against target schemas. If the model outputs bad JSON formats or invalid keys, the agent triggers a self-correction repair request, passing the traceback error back to the LLM to fix the formatting.

      ⚡ CPU Performance Tuning Guidelines

      Follow these configuration rules to maximize execution performance on local CPUs:

      • Core Alignment: Limit n_threads strictly to the number of physical CPU cores (e.g., 4 or 8) to avoid context-switching overhead.
      • Context Size Control: Limit the context size n_ctx (default: 4096) to match the document size, which reduces token evaluation latency.
      • Environment Variables: Configure shell flags to prevent thread conflicts: 
        export OMP_NUM_THREADS=4
export MKL_NUM_THREADS=4

      🎯 Accuracy Improvement Tips

      Tip for Tabular Data: When processing tables inside PDF or Word files, flat text parsing loses row and column associations. Preprocess tables into a flat string structure using row delimiters (e.g., "Col 1 | Col 2") before passing the content to the model.
      Schema Isolation Warning: Explicitly instruct the model to use null or "" for missing fields to prevent the model from inventing fallback values.

      API Reference

      `SLMDocumentParser` Initialization

      from slm_document_parser.document_parser import SLMDocumentParser

parser = SLMDocumentParser(n_threads=4)
      ParameterTypeDescription
      model_pathstrOptional custom directory containing the ONNX model files. Defaults to "../../models/phi-3.5-mini-instruct-onnx".
      n_ctxintThe maximum context window size (default: 4096). Supports up to 128,000 tokens.
      n_threadsintNumber of hardware threads allocated on CPU (default: 4).

      `parse` Method

      Extracts data matching your target structure. Include the generated output validation schema in your script:

      from slm_document_parser.document_parser import SLMDocumentParser

parser = SLMDocumentParser()

# Complex invoice target structure
target_schema = {
    "invoice_id": "string",
    "billing_date": "string",
    "line_items": [
        {"item": "string", "quantity": "number", "price": "number"}
    ],
    "total_amount": "number"
}

# Run offline parsing
result = parser.parse(file_path="invoice.docx", schema_dict=target_schema)
print(result)
