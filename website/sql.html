      SLM Text-to-SQL

      An offline natural language to SQL translation companion. Query relational databases on CPU, train specialized adapters using built-in training scripts, and ensure local data security.

      Get Started GitHub Repo
      Installation Configuration Env Variables Fine-Tuning Performance Accuracy Security

      Installation

      Terminal
      # Install from PyPI
pip install slm-text-to-sql

# Set default performance configuration (optional)
export SLM_TEXT_TO_SQL_N_THREADS=8
export SLM_TEXT_TO_SQL_MAX_TOKENS=256

      Configuration API

      Constructor Parameters

      ParameterType / DefaultDescription
      model_pathstr | NoneExplicit path to an ONNX model directory. If omitted, auto-resolves from config.yaml or downloads the model automatically.
      cache_dirstr | NoneDirectory to download/cache the model. Also settable via SLM_TEXT_TO_SQL_CACHE_DIR.
      n_ctxint | 2048Context window size in tokens. Large table schemas might require extending this. Also settable via SLM_TEXT_TO_SQL_N_CTX.
      n_threadsint | 4CPU threads for ONNX Runtime. Set to physical core count for maximum throughput. Also settable via SLM_TEXT_TO_SQL_N_THREADS.
      system_promptstr | NoneOptional custom system prompt instructions overriding the default template.
      user_inputstr | NoneOptional additional user-supplied target parameters or variables.

      generate_sql() Parameters

      ParameterType / DefaultDescription
      schemastrRequired. The CREATE TABLE schemas mapping database tables and attributes.
      questionstrRequired. Natural language database query.
      temperaturefloat | 0.0Generation temperature. 0.0 = deterministic (strongly recommended for SQL queries).
      max_tokensint | 256Max tokens for generated query. Lower = faster. Also settable via SLM_TEXT_TO_SQL_MAX_TOKENS.
      streambool | FalseIf True, enables Claude-style token streaming. The model will stream its thinking process inside <thought>...</thought> tags first, followed by the final SQL query. Returns a Python generator.
      system_promptstr | NoneOptional custom system prompt instructions overriding the default template.
      user_inputstr | NoneOptional additional user-supplied target parameters or variables.
      Quick Start
      from slm_text_to_sql import SLMTextToSQL

agent = SLMTextToSQL(n_threads=8)

schema = """
CREATE TABLE employees (
    id INT PRIMARY KEY,
    name VARCHAR(50),
    salary INT,
    department VARCHAR(50)
);
"""

query = agent.generate_sql(
    schema=schema,
    question="Get the average salary of employees in marketing"
)
print(query)
# Output: SELECT AVG(salary) FROM employees WHERE department = 'marketing';

      QLoRA Fine-Tuning Workflows

      The library includes complete training scripts to train custom adapters on your databases. Fine-tune any HuggingFace model (e.g. Qwen/Qwen2.5-Coder-1.5B-Instruct) using SFTTrainer and PEFT/QLoRA on GPU/TPU environments.

      Steps to Train

      Terminal
      # Run the built-in training & merge pipeline
python -m slm_text_to_sql.fine_tune --train --merge
      💡 Tip: The training script automatically quantizes weights to 4-bit, maps datasets into ChatML, trains adapters, and merges adapters back to output a single deployment-ready model. Refer to fine_tune.py details.

      Inference RAM usage

      1. Set n_threads Correctly

      Setting n_threads to the number of physical CPU cores (not logical hyperthreads) yields the best speed. Check your core count using nproc (Linux) or sysctl (Mac) and export it via SLM_TEXT_TO_SQL_N_THREADS.

      2. Keep schemas concise

      Only include tables and columns relevant to the user query. Feeding 100 table schemas into the context slows tokenization down. A pre-router or catalog lookup should select the relevant tables before calling the Text-to-SQL agent.

      3. Set max_tokens low

      Relational queries are typically brief. Limiting max_tokens to 128 or 256 speeds up generations by capping model exploration.

      Improving Accuracy

      1. Include Column Comments & Descriptions

      If your column names are cryptic (e.g. dept_id_ref_val), add schema comments or database descriptions to help the local model map natural vocabulary to table attributes.

      ✅ Good Schema Design:
      id INT PRIMARY KEY, -- Unique employee identifier
      sal_val INT, -- Monthly base salary in USD

      2. Use temperature=0.0

      Always generate SQL using temperature=0.0. Factual code generation tasks require greedy decoding; introducing randomness leads to invalid query structures.

      3. Include Table Relations & Constraints

      Explicitly outline primary and foreign keys in the schemas. This lets the model formulate accurate JOIN conditions and relationships.

      Security

      🔒 SQL Injection Safety: Because SLM Text-to-SQL runs offline on your local host, it doesn't execute SQL against your database directly. It only outputs query strings. You must validate and run the output query securely using parameterized query bindings or sandboxed clients.

      Adversarial Input Validation

      Sanitize user questions before passing to the SQL generator. Adversarial commands (e.g. "Show employees salary AND drop table users") could lead the model to output dangerous statements. Ensure your database connection uses restricted read-only permissions for public user queries.
