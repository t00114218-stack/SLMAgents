SLM RAG

Configuration API

Constructor Parameters

ParameterType / DefaultDescription

cache_dirstr | NoneDirectory to download/cache the model. Also settable via SLM_RAG_CACHE_DIR.

n_threadsint | 4CPU threads for inference. Set to your physical core count for best speed. Also settable via SLM_RAG_N_THREADS.

answer() Parameters

ParameterType / DefaultDescription
chunkslist[str]Required. List of document text strings to use as context. Can be empty — the model will then say it doesn't know.
questionstrRequired. The user's question to answer.
instructionstrRequired. A style or constraint directive the model must follow. E.g., "Answer concisely in JSON", "Use a formal tone".
temperaturefloat | 0.0Generation randomness. 0.0 = deterministic (fastest, most accurate for factual tasks). Use 0.5–0.8 for creative writing.
max_tokensint | 256Max tokens to generate. Lower = faster. Also settable via SLM_RAG_MAX_TOKENS.
toolslist | NoneOptional list of JSON-schema tool definitions for agentic Vector DB retrieval. See Tool Use section.
tool_executorcallable | NoneOptional fn(tool_name: str, args: dict) -> str. Called when the model needs additional context via a tool.
max_iterationsint | 5Maximum ReAct tool-calling loops. Prevents runaway inference. Set to 1 or 2 for most use cases.
Quick Start
from slm_rag import SLMRag

rag = SLMRag(n_threads=8)

chunks = [
    "NebulaCorp was founded in 2024 by Dr. Helena Vance.",
    "Their flagship product is AegisShield, used in financial organizations.",
]

answer = rag.answer(
    chunks=chunks,
    question="Who founded NebulaCorp?",
    instruction="Answer in one sentence.",
    max_tokens=128,
)
print(answer)

Performance Tuning

1. Reduce max_tokens

The single biggest lever for latency. Token generation is the bottleneck — every token takes ~65–200ms on CPU. Keep max_tokens as low as your use case permits.

  • 128 — Short factual answers (~5–10s)
  • 256 — Detailed answers (~10–20s) — default
  • 512 — Long explanations (~20–40s)

2. Use temperature=0.0 (Greedy Decoding)

Setting temperature=0.0 uses greedy (deterministic) decoding which is slightly faster and significantly more consistent for factual RAG tasks.

3. Keep Chunks Short and Pre-processed

Each chunk is injected into the prompt as input tokens. Fewer input tokens = faster first token time. Aim for chunks under 500 characters. Remove boilerplate, headers, and formatting before passing to the RAG.

4. Limit the Number of Chunks

Passing 20 chunks is 20× the prompt overhead compared to 1 chunk. Pre-filter with a lightweight embedding similarity search to pass only the top 3–5 most relevant chunks.

Optimal usage pattern
# Pre-filter with a fast embedding model first
top_chunks = embedding_search(all_docs, question, top_k=3)

# Then pass only the top-k to the SLM RAG
answer = rag.answer(
    chunks=top_chunks,
    question=question,
    instruction="Answer concisely.",
    max_tokens=128,         # keep small
    temperature=0.0,        # greedy
)

Agentic Tool Use & Vector DB Integration

When provided chunks are insufficient, the model can autonomously call tools (like a Vector DB search) to retrieve additional context before answering.

How the ReAct Loop Works

1

You call rag.answer(chunks, question, tools=tools, tool_executor=fn)

2

The model reads the chunks. If it can answer, it outputs text directly → done in one pass.

3

If chunks are insufficient, the model outputs a JSON tool call: {"tool_call": "search_vector_db", "args": {"query": "..."}}

4

Your tool_executor function runs, queries your actual Vector DB, and returns a result string.

5

The result is injected back into the context and the model generates a final answer.

Full Vector DB Integration Example (ChromaDB)

ChromaDB + SLM RAG
import chromadb
from slm_rag import SLMRag

# Setup ChromaDB
client = chromadb.PersistentClient(path="./my_db")
collection = client.get_collection("my_docs")

# Define tool schema
tools = [{
    "name": "search_vector_db",
    "description": "Searches the document database for relevant passages.",
    "parameters": {
        "type": "object",
        "properties": {"query": {"type": "string"}}
    }
}]

# Define executor that calls ChromaDB
def executor(tool_name: str, args: dict) -> str:
    if tool_name == "search_vector_db":
        results = collection.query(
            query_texts=[args["query"]],
            n_results=3
        )
        docs = results["documents"][0]
        return "\n".join(docs)[:1000]  # truncate for safety
    return "Tool not found."

# Run RAG with agentic retrieval
rag = SLMRag(n_threads=8)
answer = rag.answer(
    chunks=[],  # start with no chunks — model will use tool
    question="What is NebulaCorp's revenue model?",
    instruction="Answer formally in 2-3 sentences.",
    tools=tools,
    tool_executor=executor,
    max_iterations=2,
)
print(answer)
💡 Tip: You can pass initial chunks and tools. If the initial chunks are sufficient, the model will answer directly (fast). If not, it will call the tool to get more. This is the most efficient pattern.

Improving Accuracy

1. Write Precise Instructions

The instruction parameter is your primary accuracy lever. Be specific — vague instructions produce vague answers.

Vague (❌)Precise (✅)
"Be helpful""Answer in exactly 1-2 sentences. Only state facts present in the provided chunks."
"Answer in JSON""Return a valid JSON object with keys: 'answer' (string), 'confidence' ('high'|'medium'|'low')."
"Be concise""Answer in under 50 words. Never mention information not in the provided context."

2. Chunk Quality Over Quantity

3 high-quality, relevant chunks are far better than 20 random chunks. Pre-filter with semantic embedding search before passing to SLM RAG.

3. Use temperature=0.0 for Factual Tasks

Greedy decoding at temperature=0.0 produces the most consistent, factual answers. Only use higher temperatures for creative or stylistic tasks.

4. Tell the Model to Refuse if Unsure

Anti-hallucination instruction
instruction = (
    "Answer ONLY from the provided context. "
    "If the answer is not in the context, respond with exactly: "
    "'I cannot find this information in the provided documents.'"
)

Security

🔒 Zero data egress: All inference runs on your CPU. No queries, documents, or answers are sent to any external server. Complete GDPR/HIPAA-friendly local deployment.

Document Access Control

SLM RAG does not enforce document access control — it answers from whatever chunks you provide. You are responsible for filtering chunks based on the user's permissions before passing them to answer().

Chunk Content Sanitization

  • Remove PII from chunks before indexing if you don't want the model to reveal it.
  • Truncate very large chunks to prevent context overflow: keep chunks under 2000 characters each.
  • Don't embed binary content (PDFs, images) directly — extract text first.

Prompt Injection in Questions

Sanitize user input
def sanitize(text: str, max_len: int = 1000) -> str:
    import re
    text = text[:max_len]
    text = re.sub(r'[\x00-\x1F\x7F]', '', text)
    return text.strip()

answer = rag.answer(
    chunks=chunks,
    question=sanitize(user_question),
    instruction=sanitize(user_instruction, max_len=200),
)
