    SLM Orchestrator

    Autonomous meta-agent that inspects incoming user queries, dynamically selects appropriate sub-agents, and sequences multi-step execution graphs.

    Overview Installation Configuration Env Variables Performance

    Overview

    Autonomous meta-agent that inspects incoming user queries, dynamically selects appropriate sub-agents, and sequences multi-step execution graphs.

    🚀 Core Capabilities

    • Dynamic routing across local specialized SLM agents
    • ReAct reasoning loop with tool-execution feedback cycles
    • Parallel tool execution branches
    • Automatic fallback handling on sub-agent errors

    Installation

    Install the local CPU-optimized package using pip:

    Terminal
    # Install local CPU-optimized package
pip install slm-orchestrator

    Configuration API

    Constructor Parameters

    Instantiate SLMOrchestrator with performance and tool options:

    ParameterType / DefaultDescription
    model_pathstr | NoneLocal ONNX model path for semantic routing. Default: `None`.
    temperaturefloat | 0.0Sampling temperature for routing decisions. Default: `0.0`.
    top_pfloat | 0.9Nucleus sampling probability cutoff threshold. Default: `0.9`.
    max_tokensint | 256Maximum output token generation limit per step. Default: `256`.
    cache_dirstr | NoneOffline model cache location. Default: `None`.
    n_threadsint | 4Number of CPU thread workers. Default: `4`.

    Methods

    Method SignatureReturn TypeDescription
    route(agents, question, ...)dictRoutes user query to the best-matching agent or tool callback chain.

    Execution Method Parameters

    Complete list of execution parameters accepted by the main method:

    ParameterType / DefaultDescription
    agentslist[str] | dictList of available agent names or tool specification dictionary.
    questionstrUser query string requiring routing or multi-agent execution.
    toolslist | NoneOptional additional executable tool definitions. Default: `None`.
    tool_executorcallable | NoneCallback function executing resolved tool actions. Default: `None`.
    max_iterationsint | 5Maximum allowed reasoning iterations before termination. Default: `5`.
    system_promptstr | NoneCustom instruction prompt overriding default agent routing guidelines. Default: `None`.
    user_inputstr | NoneAdditional target parameters or contextual state data. Default: `None`.
    temperaturefloat | 0.0Sampling temperature parameter. Default: `0.0`.
    top_pfloat | 0.9Nucleus sampling probability cutoff threshold. Default: `0.9`.
    max_tokensint | 256Maximum generation token limit. Default: `256`.

    Quick Start

    from slm_orchestrator import SLMOrchestrator

orchestrator = SLMOrchestrator(temperature=0.0, top_p=0.9, max_tokens=256)
res = orchestrator.route(
    agents=["RAG", "TextToSQL", "Math"],
    question="Calculate tax for Q3 revenue",
    system_prompt="Prioritize Math agent for calculation steps",
    user_input="Tax rate: 15%",
    temperature=0.0,
    top_p=0.9,
    max_tokens=256
)
print(res)

    Environment Variables

    Configure agent parameters globally using environment values:

    Environment VariableDefaultPurpose
    SLM_ORCHESTRATOR_N_THREADS4Sets CPU inference execution threads.
    SLM_ORCHESTRATOR_CACHE_DIR~/.cache/slm-orchestrator/Default directory to store downloaded ONNX weights.

    CPU Performance Tuning

    To run the SLMOrchestrator engine efficiently on CPU under 1.5 GB memory footprint:

    • Match Threads to Core Count: Set n_threads or SLM_ORCHESTRATOR_N_THREADS to match physical CPU core count.
    • Sequential Processing: Avoid concurrent processing when batch files are large.
    • Garbage Collection: Clear variables and run gc.collect() to release model RAM blocks after execution.
