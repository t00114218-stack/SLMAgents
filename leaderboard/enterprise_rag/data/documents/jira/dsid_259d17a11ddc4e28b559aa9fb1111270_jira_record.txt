Enterprise Record: Why did the 3am nightly release pipeline stop uploading buil

Document ID: dsid_259d17a11ddc4e28b559aa9fb1111270
System Source: jira
Details & Summary:
The nightly pipeline's upload step runs `/usr/local/bin/artifact-uploader` via `sudo` to set up ephemeral credentials, but the tenant-wide Security change (SUDO-2026-031) removed the wildcard sudoers rule for the `ci-agent` group. As a result, `ci-agent` was no longer in sudoers, `sudo` returned "permission denied," and the upload step exited with code 126.

- The nightly pipeline upload step runs /usr/local/bin/artifact-uploader via sudo to set up ephemeral credentials.
- A tenant-wide security change (SUDO-2026-031) removed the wildcard sudoers rule for the ci-agent group.
- After the security change, the ci-agent group was no longer allowed to use sudo.
- Because ci-agent was not in sudoers, sudo returned permission denied and the upload step failed (exited with code 126), so artifacts were not uploaded.

Additional Enterprise Context: Verified in production cluster telemetry and internal system documentation.
