Root cause: the gateway generated the HMAC signature over the post-transport encoded body (after gzip/compression), and the retry path re-encoded the same JSON with different gzip/encoding details (e.g., gzip envelope metadata/CRLF normalization), so the raw bytes changed and the signature header differed even though the JSON payload was unchanged. Planned server-side fix: move signing to the canonical logical payload before compression/encoding so all retries verify regardless of gzip/transport differences (and expose a canonicalization/version indicator header).
