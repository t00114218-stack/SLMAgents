Enterprise Record: During the us-east canary that normalized/rotated the sessio

Document ID: dsid_7fd136dd100c4c9cbbe1958c94c26152
System Source: jira
Details & Summary:
Root cause: the edge canary rewrote/normalized the Set-Cookie domain (e.g., to .redwood.ai) and long-poll streaming clients kept sending the old host-scoped cookie; session-manager treated the cookie domain as mismatched/invalid, considered the session unauthenticated for pin reconciliation, dropped the pinned routing key, and the router then selected the fallback model. Immediate mitigations: platform rolled back/disabled the cookie-domain rewrite for the us-east canary cohort; customer was instructed to force a session refresh (POST /v1/sessions/refresh) to restore the pin for affected long-poll sessions.

- The us-east edge canary rewrote or normalized the Set-Cookie Domain attribute to a cross-subdomain domain (for example, .redwood.ai).
- Long-poll streaming clients continued sending an old host-scoped session cookie after the domain normalization.
- In the edge to session-manager flow, session-manager treated the cookie as domain-mismatched or invalid and considered the session unauthenticated for pin reconciliation.
- Because the session was treated as unauthenticated, session-manager dropped the pinned routing key (pinned model version).
- With the pinned routing key dropped, the router selected a fallback model.
- Platform-side mitigation was to roll back or disable the cookie-domain rewrite for the us-east canary cohort.
- Customer-side mitigation was to force a session refresh via POST /v1/sessions/refresh to restore the pin for affected long-poll sessions.
