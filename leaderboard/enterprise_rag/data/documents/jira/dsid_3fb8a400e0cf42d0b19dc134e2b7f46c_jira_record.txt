Enterprise Record: In a Private/VPC deployment, some users could complete SAML 

Document ID: dsid_3fb8a400e0cf42d0b19dc134e2b7f46c
System Source: jira
Details & Summary:
The IdP upgrade caused the comma-separated SAML "groups" attribute to be emitted with a leading UTF-8 BOM (U+FEFF / bytes EF BB BF), so the first group value was actually BOM-prefixed and didn't exactly match the configured admin group string. The server-side fix was a patch to normalize/sanitize the groups attribute before role mapping (strip BOM/invisible control characters, then TrimSpace and split on commas), restoring correct first-group matching.

- The IdP upgrade caused the comma-separated SAML groups attribute to be emitted with a leading UTF-8 BOM (U+FEFF, bytes EF BB BF).

- The server-side patch fixed the issue by normalizing and sanitizing the groups attribute before role mapping (stripping BOM and other invisible control characters, then trimming whitespace and splitting on commas).
