Enterprise Record: In the EU hosted API, streaming generate requests over HTTP/

Document ID: dsid_ab50b630b14e4bfda87847286157b739
System Source: slack
Details & Summary:
Root cause was the midproxy NGINX rejecting the request because the client's ~12KB base64 X-User-Meta header exceeded its default header/buffer limits ("client sent too large header"), causing NGINX to abort the upstream connection and the edge Envoy to surface it as an intermittent HTTP/2 streaming 502 ("disconnect/reset before headers"). Mitigation deployed was an edge header-filter that drops X-User-Meta when it is >4096 bytes (oversized header is removed so the request can proceed), which stopped the 502s.

- The root cause was the midproxy NGINX rejecting requests because the X-User-Meta header of about 12KB exceeded its default header or buffer limits (client sent too large header).
- NGINX aborting the upstream connection caused the edge Envoy to surface the failure as an intermittent HTTP/2 streaming 502 (disconnect or reset before headers).
- The mitigation was an edge header filter that drops the X-User-Meta header when it is larger than 4096 bytes so the request can proceed.
- Dropping oversized X-User-Meta headers at the edge stopped the 502s.
