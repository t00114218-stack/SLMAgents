Details & Summary:
Use the playbook's evidence-first pipeline: (1) sample 1-5% of production traffic for 1-2 weeks and emit compact workload signatures (e.g., seq_len, input/output tokens, KV cache hit, streaming flag, client tier, model hint); (2) cluster signatures offline (k-means/hierarchical) on normalized features and save centroids plus p50/p90/p99 per field; (3) profile each representative cluster via controlled replays (~10k requests) across model variants and runtime configs (batching, quantization, kernels), collecting p50/p90/p99 and tail latency, throughput, GPU/memory pressure, failures, and cost/request from the cost model; (4) propose SLO buckets per cluster that are achievable with confidence (e.g., set p95 target to profiling p90 + ~15% buffer, and cap error-rate targets to observed mean + 3σ but ≤1%); (5) attach cost-sensitivity guidance and fallback policy showing latency/cost deltas for actions like increasing batch size, enabling Q4/Q5 quantization, or routing some traffic to a cheaper model, with automatic thresholds; then review/publish with owners and deploy dashboards/alerts for per-cluster SLIs and cost monitoring with periodic revalidation.

- Sample about 1 to 5 percent of production inference traffic for about 1 to 2 weeks and emit compact workload signatures per request (for example sequence length, input and output tokens, KV cache hit, streaming flag, client tier, model hint).
- Cluster the collected workload signatures offline (for example using k-means or hierarchical clustering) on normalized features and record cluster centroids plus per-field p50, p90, and p99 statistics.
- For each representative cluster, run controlled replay profiling at roughly 10,000 requests across model variants and runtime configurations (for example batching, quantization, kernels).
- During profiling, collect latency distribution metrics (p50, p90, p99 and tail latency) along with throughput, GPU and memory pressure, failures, and cost per request derived from a cost model.
- Define latency SLO buckets per cluster using profiling evidence, for example setting a p95 latency target to about the profiled p90 plus an additional buffer (around 15 percent).
- Define error rate targets using observed error evidence, for example capping error rate targets to the observed mean plus 3 standard deviations but not exceeding 1 percent.
- Attach cost sensitivity guidance and a fallback policy per cluster by quantifying latency and cost deltas for actions like increasing batch size, enabling Q4 or Q5 quantization, or routing some traffic to a cheaper model, with automatic thresholds.
- Publish the resulting per-cluster SLOs with service owners and deploy dashboards and alerts for per-cluster SLIs and cost monitoring, with periodic revalidation.
