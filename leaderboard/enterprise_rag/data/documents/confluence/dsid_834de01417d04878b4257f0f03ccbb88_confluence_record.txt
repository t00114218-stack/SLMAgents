Details & Summary:
In v1, the manifest does not embed a `signature` blob; integrity is expressed via an optional `integrity` field (one of `none`, `sha256-only`, `sigstore-oidc`) and, when `integrity` != `none`, an `integrity_ref` URI that points to the signature/envelope material. The earlier draft instead listed an optional embedded `signature` field for integrity verification.

- The answer must state that v1 no longer uses an embedded `signature` field in the manifest.
- The answer must identify `integrity` as the v1 field used to describe the integrity mechanism.
- `integrity` must be described as optional in v1 (not required).
- The answer must list the v1-supported `integrity` values: `none`, `sha256-only`, and `sigstore-oidc`.
- The answer must state that `integrity_ref` is a URI/reference to signature/envelope material used when `integrity` is not `none`.
- The answer may mention the earlier draft had an optional `signature` blob, but it must clearly distinguish that as pre-v1/draft behavior.
- The answer must not claim v1 embeds a cryptographic signature directly in a `signature` key.
- The answer must not introduce unsupported integrity mechanisms (e.g., PGP, JWT-only signing) not listed in the v1 document.
